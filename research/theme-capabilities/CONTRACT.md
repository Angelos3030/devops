# Συμβόλαιο δυνατοτήτων theme

Τι επιτρέπεται να αλλάξει ο πελάτης, ανά theme — και ποιος το επιβάλλει.

Το ίδιο συμβόλαιο εξυπηρετεί τρεις καταναλωτές: το UI προσαρμογής, τον έλεγχο
στο backend, και τον μελλοντικό συνομιλιακό editor. **Κανένας δεν κρατά δικό του
αντίγραφο.**

---

## Πού ζει

| αρχείο | ρόλος |
|---|---|
| `research/theme-library/capabilities.py` | **ΚΑΝΟΝΙΚΗ ΠΗΓΗ** — το μόνο που γράφεται με το χέρι |
| `sites/lib/templates/capabilities.js` | παραγόμενο · UI + AI editor |
| `src/theme_capabilities.py` | παραγόμενο · έλεγχος backend |
| `scripts/apply_capabilities.py` | ο μεταφραστής |
| `tests/test_theme_capabilities.py` | κόβει αν τα δύο παραγόμενα αποκλίνουν |

Δύο παραγόμενα αρχεία δεν είναι αντιγραφή: το frontend είναι JavaScript και το
backend Python, δεν διαβάζουν το ίδιο αρχείο. Και τα δύο βγαίνουν από την ίδια
πηγή, και το test αποτυγχάνει αν διαφέρουν έστω σε ένα theme.

Χειρόγραφη αλλαγή σε παραγόμενο αρχείο χάνεται στην επόμενη εκτέλεση. Γι' αυτό
γράφεται προειδοποίηση στην κορυφή τους.

## Πώς προέκυψε η ταξινόμηση

Η αντίθεση επαληθεύτηκε **πρώτη**: 58 themes × 6 παλέτες × 2 viewports, 6.648
κείμενα, **0 αποτυχίες**. Κανένα theme δεν αποκλείεται για λόγους
προσβασιμότητας.

Ο αποκλεισμός είναι **αποκλειστικά σχεδιαστικός**, από οπτική αξιολόγηση κάθε
theme με το demo business του δικού του vertical (CLAUDE.md §7β):

| κατηγορία | πλήθος | κριτήριο |
|---|---|---|
| **A** | 36 | η παλέτα διαβάζεται ως σκόπιμη σχεδίαση → και οι 5 |
| **B** | 12 | μόνο ορισμένες οικογένειες στέκουν → υποσύνολο |
| **C** | 10 | η αλλαγή είναι αόρατη ή καταστρέφει την ταυτότητα → κανένας έλεγχος |

Δύο τυπικοί λόγοι για **B**: η παλέτα βάφει τη *φωτογραφία* (duotone — πράσινο
γυμναστήριο), ή ένα δεύτερο accent είναι η ίδια η ταυτότητα (`volt`: το neon
lime **είναι** το «volt»).

Ο τυπικός λόγος για **C**: η ταυτότητα είναι η φωτογραφία και η παλέτα αλλάζει
μόνο ένα κουμπί. Το `coast` μετρήθηκε στο **1,9%** οπτική διαφορά. Έλεγχος που
δεν κάνει τίποτα ορατό είναι κενή υπόσχεση προς τον πελάτη.

## Το API

```js
import { getThemeCapabilities, isAllowed } from '@/lib/templates/capabilities'

getThemeCapabilities('coast')
// { cls: 'C', mode: 'light', palettes: [], typography: true, logo: true }
```

```python
from src import theme_capabilities as tcaps

tcaps.is_allowed('coast', 'set_palette', 'forest')   # False
```

### Πεδία

| πεδίο | σημασία |
|---|---|
| `cls` | `A` / `B` / `C` — η ταξινόμηση **παλέτας** |
| `mode` | `light` / `dark`, **μετρημένο** από φωτεινότητα επιφάνειας, ποτέ από όνομα |
| `palettes` | οι επιτρεπτές οικογένειες· κενό = χωρίς έλεγχο |
| `typography` | αλλάζει ορατά η γραμματοσειρά; (οριστικοποιείται στο Phase 3) |
| `logo` | δέχεται λογότυπο πελάτη — **58/58** |

Το `mode` δεν είναι διακοσμητικό: το `dispatch` έχει φωτεινότητα επιφάνειας
**0,004**. Χωρίς αυτό, μια ανοιχτή παλέτα το αντέστρεφε και το κείμενο έπεφτε
σε **1:1**. Οι σκούρες παραλλαγές επιλέγονται αυτόματα από το `mode`.

## Επιβολή

**Η απόκρυψη control στο UI δεν είναι επιβολή.** Είναι ευγένεια προς τον χρήστη.
Ο κανόνας επιβάλλεται στο `put_content`, στην ίδια συνάρτηση που γράφει στη βάση:

```python
elif k == "palette":
    if v in {...} and tcaps.is_allowed(_theme_of(client_id, body.content), "set_palette", v):
        clean[k] = v
```

Το `_theme_of` κοιτά το theme που θα **ισχύει μετά** την αποθήκευση: αν ο
πελάτης αλλάζει ταυτόχρονα theme και παλέτα, κρίνεται με το **νέο** theme.

Επαληθεύτηκε με χειροποίητα αιτήματα που παρακάμπτουν εντελώς το UI — **9/9**.

## Παραδείγματα

### Επιτρεπτή

```
theme: bigspring-advisory   (κατηγορία A)
set_palette('forest')       -> ΔΕΚΤΟ
```
Γράφεται, φαίνεται στο preview, επιβιώνει reload.

### Περιορισμένη

```
theme: forge                (κατηγορία B, επιτρεπτό: warm)
set_palette('warm')         -> ΔΕΚΤΟ
set_palette('ocean')        -> ΑΡΝΗΣΗ
```
Το `forge` έχει κίτρινη ταινία κινδύνου ως υπογραφή· εκτός warm χάνεται.

### Μη υποστηριζόμενη

```
theme: coast                (κατηγορία C)
set_palette('forest')       -> ΑΡΝΗΣΗ
set_palette('original')     -> ΔΕΚΤΟ
```

Το `original` επιτρέπεται **πάντα**, σε κάθε κατηγορία: είναι επιστροφή στην
ταυτότητα του theme, όχι προσαρμογή.

## Για τον μελλοντικό AI editor

Ο editor **δεν υλοποιείται εδώ**. Το συμβόλαιο υπάρχει ώστε ένα μελλοντικό
`EditPlan` να ρωτά **πριν** προτείνει.

Η σειρά είναι δεσμευτική:

1. `getThemeCapabilities(themeId)`
2. αν η ενέργεια δεν επιτρέπεται → **μην την προτείνεις καν**
3. αν επιτρέπεται → πρότεινε, δείξε draft, ζήτα έγκριση
4. το backend ελέγχει **ξανά** στην εγγραφή

Το βήμα 4 δεν είναι περιττό. Ο editor είναι γλωσσικό μοντέλο: μπορεί να
προτείνει ό,τι να 'ναι. Η πύλη είναι το backend.

Όταν ο πελάτης ζητά κάτι μη υποστηριζόμενο, η απάντηση λέει **τι ισχύει**, χωρίς
εσωτερικά ονόματα και χωρίς παραπομπή σε ανύπαρκτο «τεχνικό» — βλ.
`src/site_actions.py`:

> «Αυτό το σχέδιο κρατά τα δικά του χρώματα. Αν θέλεις άλλα χρώματα, μπορώ να
> σου προτείνω σχέδιο που τα υποστηρίζει.»

## Τι ΔΕΝ καλύπτει ακόμη

- **Τυπογραφία**: 23/58 αλλάζουν ορατά· τα υπόλοιπα 35 γράφουν σκληρά
  `font-family`. Η μετάβαση δεν έχει γίνει — το πεδίο `typography` δηλώνει
  σήμερα *τι φαίνεται*, όχι *τι είναι εγκεκριμένο*. Οριστικοποιείται με
  ταξινόμηση `T-A` / `T-B` / `T-C`.
- **Σειρά φωτογραφιών**: ο πίνακας `assets` δεν έχει στήλη ταξινόμησης.
- **Ανά-παλέτα τυπογραφία**: δεν υπάρχει συνδυαστικός περιορισμός.
